## 一、三步跑起来

```bash
# 1) 进入学号目录（main.py 就在这里）
cd 3224004083

# 2) 装上开发工具（可选，程序本身零依赖，不装也能跑）
pip install -r requirements-dev.txt

# 3) 运行：三个参数都是文件的绝对路径，顺序不能换
python main.py <原文文件> <抄袭版论文文件> <答案文件>
```

示例：

```bash
python main.py sample/orig.txt sample/orig_0.8_dis_2.txt answer.txt
type answer.txt          # Windows
# cat answer.txt         # macOS / Linux
```

答案文件里只有一行内容，形如：

```text
0.93
```

**程序不在终端打印结果**，结果只写进第三个参数指定的文件——这是作业明确要求的。

### 参数顺序（写错顺序结果就没有意义）

| 位置 | 含义 |
|---|---|
| 第 1 个 | 论文**原文**文件的绝对路径 |
| 第 2 个 | **抄袭版**论文文件的绝对路径 |
| 第 3 个 | **答案**输出文件的绝对路径 |

### 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 正常结束，答案已写出 |
| `1` | 运行期错误（文件不存在、路径是目录、文本为空、答案不可写），**已有答案文件保持原样** |
| `2` | 参数个数不是三个，终端打印用法 |

## 三、常用命令

### 跑单元测试

```bash
# 方式一：pytest（需 pip install -r requirements-dev.txt）
python -m pytest tests -q

# 方式二：标准库 unittest，零依赖
python -m unittest discover -s tests -t .
```

### 一键出覆盖率报告

```bash
python tools/test_coverage.py
```

产出：终端表格 + `docs/coverage_report.txt` + `docs/coverage_chart.png`
（博客要的"覆盖率截图"）+ `docs/coverage_html/index.html`（可点开的明细）。

### 一键出性能分析报告

```bash
python tools/perf_analysis.py
```

产出：`docs/perf_report.txt` + `docs/perf_chart.png`（热点函数图）+
`docs/normalize_compare.png`（优化前后对比图）。
报告里的数字会随机器负载波动，所以表格同时给出「最快 / 中位数 / 最慢」三个值。

### 一键出代码质量报告

```bash
python tools/code_quality.py
```

产出：`docs/code_quality_report.txt` + `docs/code_quality.png`（评分卡，可截图）。
当前结果：**pylint 10.00 / 10，0 条警告**。

### 重新生成测试样例

```bash
python tools/make_samples.py     # 生成 sample/ 下的 12 份样例
python tools/run_samples.py      # 批量验收，检查分数是否落在期望区间
```

### 批量查重（扩展功能）

```bash
python tools/batch_check.py sample/orig.txt sample/ --csv result.csv
```

一次算完一个目录里的所有抄袭版文件，输出表格并可导出 CSV。

## 四、换成老师的官方样例怎么用

作业里说「我们提供一份样例，`orig.txt` 是原文，其他 `orig_add.txt` 等均为抄袭版论文」。
拿到官方样例后：

```bash
# 1) 把官方样例拷进 sample/（覆盖同名的自造样例）
# 2) 先单独跑一个确认没问题
python main.py sample/orig.txt sample/orig_add.txt answer.txt
type answer.txt

# 3) 全部跑一遍看分数分布是否合理
python tools/batch_check.py sample/orig.txt sample/
```

如果某个样例算出来的分数和你预期差距很大，把文件名和分数记下来，那是算法需要调整的信号。

## 五、评测约束自查（作业的硬性要求）

| 要求 | 本程序的做法 | 自查方式 |
|---|---|---|
| 命令行三参数 | `main.py` 严格校验 `len(args) == 3` | `python main.py` → 退出码 2 |
| 入口文件名 `main.py` | 是 | — |
| 答案精确到小数点后两位 | `Decimal` + `ROUND_HALF_UP` | 见 `tests/test_cli.py::FormatScoreTest` |
| 5 秒内给出答案 | 最长测过的 55 万字符输入，中位数 1.74 秒 | `python tools/perf_analysis.py` |
| 内存不超过 2048 MB | 同一输入峰值 7.1 MiB | 同上 |
| 不连接网络 | 只 import 标准库，无任何网络调用 | `grep -r "socket\|urllib\|requests"` 无结果 |
| 不读写其他文件 | 只打开命令行给出的三个路径 | 代码里只有 `reader.py` / `writer.py` 各一处 `open` |
| 不发生异常退出 | 所有可预期错误转成退出码 1 / 2 | `tests/test_cli.py` + `tests/test_edge_cases.py` |
